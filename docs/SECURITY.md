# 安全与数据保护

**简体中文** · [English](SECURITY.en.md)

ST-Vault 是单管理员的个人自托管应用，不是多租户服务，未经过独立安全审计。只在本机或受信任网络开放，远程使用 HTTPS 并限制入口。

## 认证与凭据

- 首次先设置并确认六位 PIN，随后进入工作台；连接原站账户是可选的后续操作。受限初始化许可不能读取账户、媒体或管理 API。
- PIN 使用随机盐和 scrypt 派生保存。验证有持久失败计数与来源限流，六位数字仍不适合公开暴露；首次初始化前防止他人抢先接管。旧密码部署先验证旧密码再迁移。
- 管理员会话使用 HttpOnly、SameSite=Strict Cookie，默认有效期七天；退出撤销当前客户端会话。PIN 与原站账户互相独立。
- 原站登录、动态码与真人验证在用户自己的浏览器完成，只粘贴导出的 Cookies；不接收原站密码或代替验证。
- Cookies 仅用于账户资料和关注清单。状态、HLS 与媒体拉取匿名进行，不因此获得私密或付费内容权限。
- 保存的 Cookies 和手动密钥使用用途隔离的 AES-256-GCM 加密，主密钥在 data/private；常规状态接口不回显已保存的值。只有管理员明确断开账户时，受 HTTPS/局域网私有 IP/回环限制的不可缓存响应才一次性返回原 Cookies，供重新连接。Cookies 草稿保存在当前浏览器、当前 ST-Vault 地址的 localStorage 中，不加密且不会因刷新或退出本地管理员会话自动清除；手动清空或切换站点会删除。仅在受信任的浏览器配置中使用，浏览器数据清理也会清除草稿。断开账户会删除凭据、归档主播并停录，保留媒体。

默认 Compose 只绑定 127.0.0.1:10002。公网 IP 和域名提交 PIN 或 Cookies 需要 HTTPS；私有 IP 的局域网 HTTP 允许使用，但 PIN、Cookies 和会话会明文传输，仅用于可信局域网；反向代理保留 Host 并支持 SSE。`STV_SECURE_COOKIE=1` 不会自动创建证书或 TLS，不能用它代替真正的加密传输。

## 存储边界

PostgreSQL 只监听应用私有 Unix socket，不映射 5432。数据库目录必须是可靠本地文件系统，不支持 SMB/NFS；同一媒体库只允许一个实例写入。完整状态根和备份包含敏感配置，限制文件权限。控制宿主机或应用进程的人仍能访问数据，媒体没有应用层静态加密。

停写后备份完整 data 与 media。只迁移 media 可以重建媒体索引并浏览管理，但不会恢复 PIN、Cookies 和私有密钥；新部署须重新设置。不能只复制 PostgreSQL 主表、零散 WAL 或单份 journal。详细操作见[使用手册](../README.md#备份恢复与更新)。

缩短保留期、手动删除会永久释放媒体；喜欢只保护自动保留清理。磁盘阈值、重试和恢复机制不能替代备份，也不保证所有硬件和网络下连续录制。

## 反馈与依赖

不要公开 Cookies、令牌、完整请求头、HAR、数据库或私人录像。安全漏洞使用仓库已启用的私密报告入口；没有该入口时通过维护者明确公布的私密渠道联系。项目不承诺未公布的邮箱、响应期限或历史版本支持。

提供受影响提交、部署方式、最小复现和脱敏错误码。CI 对生产依赖执行高危/严重漏洞门槛，但审计只是执行时快照，不代表不存在未知漏洞；开发工具链不进入运行镜像。第三方许可见[声明](third-party.md)。
