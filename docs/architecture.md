# 架构与存储

**简体中文** · [English](architecture.en.md)

ST-Vault 面向单管理员、多客户端。React/Vite 工作台通过 REST 与 SSE 连接 Fastify；单容器内运行 Node、PostgreSQL 18 和截图用的 FFmpeg。生产镜像没有浏览器、GPU 解码组件或自动密钥提取器。版本和依赖以 [package-lock.json](../package-lock.json) 与 [Dockerfile](../deploy/Dockerfile) 为准。

## 数据流与模块边界

存储、HLS 对齐和媒体目录日期始终使用 UTC。部署 `TZ` 经服务端校验后由会话接口传给工作台，统一所有客户端的显示时区，与界面语言无关。日历导航使用当地午夜/中午的离散槽位（`@date-fns/tz` 处理夏令时），媒体时长仍取真实 UTC 差值；不能用固定 24 小时替代自然日。

```text
原站 Cookies → 账户资料 / 完整关注清单
匿名状态和 HLS → 每主播共享流入口 → 浏览器直播
                               → 原流落盘 → 录像单元 → 后台截图
浏览器操作 → HTTP → 归档 worker → 媒体库日志 + PostgreSQL 热索引
```

## 状态、录制与网络

“全部主播录制”是持久化的录制默认策略，不是当前列表开关的汇总。设置时在同一归档事务中更新默认值和全部未归档主播；后续新加入或重新关注者继承该值，普通清单刷新及上下线不覆盖单个主播的手动选择。归档仍强制停止录制。策略随媒体库日志恢复，前端通过统一同步通知读取；无既存策略时默认关闭，不推断用户曾经的批量操作意图。

状态是带观测时间与有限租期的证据，不是永远有效的布尔值。失败和 UNKNOWN 不立即改写已知状态，也不续租。不同的已知状态通过追加匿名观测确认，确认后将转换边界回溯到首次有效候选观测；隐私撤销不等历史确认。重启与租期到期保留未知空档，不伪造离线或连续在线。具体实现及故障测试位于 [provider](../apps/server/src/provider) 与 [archive](../apps/server/src/archive)。

历史事件按递增 ID 分页；发生时间与发现时间分开，迟到确认不打乱已读游标。运行事件记录正常关闭和重启后发现的异常关闭；最后心跳只能给出故障时间下界，不能推断精确断电时刻。事件、状态与已读位置进入可恢复媒体库；工作台不再绘制橙色停机覆盖块。

每位主播共享一条正常上游生产链，直播消费内存中的媒体，录制独立顺序提交，不等落盘才供直播。录制保存最高可用源画质，不转码。优先使用 HLS PROGRAM-DATE-TIME 定位墙钟；没有可靠时间的片段保持未定位，不用下载时间冒充源时间。

网站域名在账户连接后锁定，清单与匿名资料、状态共用该来源。HLS 默认节点为 `edge-hls.doppiocdn.net`，后续使用持久化的手动选择。更换节点后，每个生产者取消旧路请求并重新解析所选节点，保留已发布缓冲和录制写队列。测速只由用户发起，顺序对各节点读取最多 2 MiB 的实际分片，结果用于展示和排序。

## 录像单元与前端一致性

完整源分片只能归属一个稳定录像单元。约分钟节奏建立单元，不在自然分钟边界切视频；短暂断流不直接拆成新身份。代表截图优先使用单元首个分片中的可解码画面，增长中的单元保持取样锚点与 URL 稳定。截图、喜欢、删除与回放吸附共同使用单元身份。

直播真实时间、播放游标、已提交末端各自独立。点击截图只定位播放，不冻结直播窗口；拖选才固定范围。服务端生成有限空档与压缩后的分页格位，客户端不能用分钟数推算页码。截图未生成和媒体不存在是不同状态。

喜欢先持久接纳并发布逻辑保护，再分批整理；开放单元后续成员继承保护。删除先接纳持久意图、逻辑隐藏，再准备成员和分批回收；确认时封闭开放单元，之后的新录像不混入旧任务。重启继续未完成步骤。全选使用冻结选择令牌和显式例外，不将全库成员下载进浏览器；个人版本和删除世代阻止迟到结果覆盖新操作。

前端按业务 scope 管读取与取消，SSE 提供失效通知，不能将它当完整业务数据。当前时间线每包三行、两包并行；缓存有界，优先可见行。相同主体对象复用；连接线几何局部订阅；动画按实际几何变化触发，并批量测量后写入。精确播放游标不驱动整块覆盖线，存档时间映射使用累计索引二分定位。

列表像素位置由原生滚动管理，仅可见行集合变化才更新虚拟列表；位置恢复与连接线仍使用精确偏移。覆盖线每行使用一个 SVG、至多 15 条密度路径，保留空档与不足一像素的可见标记，避免每个历史片段独立参与 DOM 布局和玻璃材质动画。绘制聚合不改变截图、选区吸附、喜欢或删除所用的原始时间数据。

列表排序、筛选及增删共用视口级过渡：先确定最终顺序与浏览锚点，再以 Web Animations 平移可见整行。远处目标截到视口边缘，离场 DOM 只保留约一屏、360ms，不额外挂载远处行或加载其图片；空位自然补齐。连续更新从当前动画位置接续，滚动、拖选、调整视图优先中断动画。封面与时间线同行移动，选区和播放器连接线同步跟随；沿用项目动效时长和缓动，不新增动画依赖。

## 并行与任务调度

[execution-policy.ts](../apps/server/src/runtime/execution-policy.ts) 根据有效 CPU、内存和容器限制规划网络、解码、文件 IO、发布及数据库容量。录制路数不设固定上限，但所有缓冲和工作队列仍有资源边界。提高并发不保证机械盘吞吐线性增长。

数据库使用普通读取、播放、后台、快照和写入专用池。前台批次与后台有界步骤公平交替；补建录像单元索引属于后台。唯一 journal writer 保证日志顺序与 fsync 一致性，不是遗留的 SQLite 限制。交互/播放只读事务的单条 SQL 上限为 15 秒，不含连接等待，不是端到端取消；回滚失败的快照连接直接丢弃。

状态面板聚合同步、封面、录制、截图、删除、喜欢整理、保留清理、完整性与检查点等任务。业务时钟统一调度，慢任务不重叠；解码、重连和超时属于各自操作生命周期，不把每个计时器都变成面板任务。正常退出先停止生产，再排空已接纳工作，最后关闭归档与 PostgreSQL。

## 存储与恢复

`data` 保存部署私有配置和 PostgreSQL 热索引；`media` 保存可迁移媒体库。两者可分别挂载 SSD 与机械盘，数据库要求本地文件系统；同一库只允许一个实例写入。

```text
data/
  postgres/18/                    PostgreSQL 集群
  private/                        配置加密主密钥与数据库凭据
  logs/                           轮转日志
  backups/                        存在旧库升级时的冻结副本
media/
  library.json                    库身份与检查点引用
  catalog/                        当前及上一份 NDJSON 检查点
  postgres-journal/               顺序提交日志
  subjects/stripchat-<ID>/
    images/                       封面、头像
    recordings/YYYY-MM-DD/HH/     UTC 日/小时分桶的原始分片
    recordings/unlocated/         未可靠定位的媒体
    recordings/.staging/          尚未发布的写入
    thumbnails/YYYY-MM-DD/HH/     JPEG 与来源校验信息
```

主播键为 `stripchat:<ID>`，名称与自动曾用名只是资料。库内使用相对路径；日/小时分目录控制单目录规模，检索通过数据库索引完成，不在每次请求中扫描录像文件。PIN、Cookies、解密密钥及私有网络配置不进入媒体库检查点。

媒体先临时写入、fsync、原子发布。数据库实际行变更先写媒体库日志并 fsync，再提交热索引并应答。检查点固定一致快照后流式导出，不把全库载入内存；保留当前、上一检查点及恢复所需日志。热索引缺失从检查点和日志恢复，完整记录校验错误或序号缺口明确拒绝，不能吞掉损坏。

截图任务是可恢复的后台工作，已有有效 JPEG 经图片和来源校验后复用。删除物理回收不长期占用录制写锁；同主播有序、不同主播有界并行。已提交墓碑后的文件删除失败进入重试，不将整个媒体库判为损坏。

当前媒体库清单格式为 2，PostgreSQL catalog schema 为 1。保留的旧双目录 SQLite 格式 5 导入是一次性升级通路，不是日常存储。备份、移动及旧版本回退限制见[使用手册](../README.md#备份恢复与更新)与[维护说明](CONTRIBUTING.md#旧部署升级)。
